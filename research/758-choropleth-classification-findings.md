# MapsOfBharat Choropleth Brief: Classification, Colour, and the Area-Bias Problem

## Executive Summary

The owner's complaint bundles two independent defects. (1) "One colour dominates" is a **classification-method artifact**: any linear-domain classifier (equal-interval, standard-deviation, untransformed continuous, or quantile once near-zero mass crosses a derivable threshold) collapses most of India's ~735 districts into one class on right-skewed or zero-inflated metrics. This is mechanistically inevitable on skewed data, not a data defect, and is fixable per-metric via the existing `metrics.default_scale` column. (2) "Extremes land in tiny, invisible districts" is a separate, well-documented phenomenon — **area-size bias** — caused by polygon area dominating retinal weight regardless of colour. No classification method, palette, or class count touches it; only a geometry- or symbol-level remedy does.

Both halves are real, fixable defects — not "the data is just like that." Top three actions: **(a)** compute skewness and near-zero fraction per metric offline, route each through a decision rule instead of one global default; **(b)** add a data-driven `circle-radius` proportional-symbol layer, decoupled from polygon area — cheap, mobile-safe, zero compliance risk; **(c)** do not adopt cartogram-family remedies as default or share-card — India's geospatial law is silent on them, zero precedent exists, and they shrink exactly the border-sensitive districts (Ladakh, Arunachal) that have already triggered real backlash in a non-cartogram case.

## Q1. Diagnosis

**Verdict: (a).** Classification-method choice — not (b) an unavoidable data property, not (c) area-vs-value bias (a separate, additive problem, see Q6).

**upi_value_per_capita** (heavy-tailed): any linear-domain classifier maps the full [min, max] to colour position. A handful of extreme districts (Mumbai, Bengaluru Urban, Chennai, Delhi) stretch that range right while most districts cluster low; equal-width bins then place ~85–90% of districts in the bottom class or two, by construction. **buddhist_pct** (zero-inflated): quantile fails via *tie-collapse* — breakpoints landing inside a tied/near-zero mass get pushed into the next class ([GeoDa](https://geodacenter.github.io/workbook/3a_mapping/lab3a.html), [PySAL](https://github.com/pysal/mapclassify/blob/main/mapclassify/classifiers.py)). At k=5, an interior breakpoint collapses whenever near-zero fraction p ≥ i/5; buddhist_pct's p=0.783 collapses 3 of 4 breakpoints (just under the p≥0.80 total-collapse line) — arithmetic, not a bug.

(b) is a contributor, not the cause: the skew is real, but skew alone doesn't force monochromacy — Jenks (already shipped) or a log-transformed continuous ramp on the same data would not produce it. (c) is real but orthogonal — it makes extreme districts invisible regardless of colour, and persists under perfect classification. Fix (a) via Q2, fix (c) via Q6; neither substitutes for the other.

## Q2. Method-Selection Decision Rule

Compute offline per metric, over non-null values (n ≤ 735): **skew** = bias-corrected Fisher-Pearson G1 (matches `scipy.stats.skew(bias=False)`); cutoffs |G1|<0.5 symmetric, 0.5–1.0 moderate, ≥1.0 highly skewed — generic descriptive-statistics convention ([Bulmer 1979](https://brownmath.com/stat/shape.htm)), not validated against choropleth outcomes, but the best available proxy. **p_near_zero** = exact-0 fraction for count/share metrics; value ≤1% of (max−min) for continuous ratio metrics. **Bimodality coefficient** BC=(skew²+1)/[kurtosis+3(n−1)²/((n−2)(n−3))], flag BC>0.555 ([Pfister et al. 2013](https://www.frontiersin.org/articles/10.3389/fpsyg.2013.00700/pdf)) — advisory only, skewed-unimodal data can false-positive. **has_reference**/**is_bounded_pct** are metadata flags, not inferred. Robustness cross-check: MAD-based modified z-score Mi=0.6745(xi−median)/MAD, flag |Mi|>3.5 ([NIST NISTIR 8526](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=957454)); a stricter, actively-cited alternative uses 2.5×MAD ([Leys et al. 2013](https://dipot.ulb.ac.be/dspace/bitstream/2013/139499/1/Leys_MAD_final-libre.pdf)) — real disagreement, use 3.5, diagnostic-only.

| Condition | Route |
|---|---|
| `has_reference` (e.g. sex_ratio) | **NEW**: manual/defined-interval, diverging, critical break pinned at the external reference (1000 for sex_ratio, not the median), k=5 asymmetric |
| `p_near_zero ≥ 0.80` (=(k−1)/k) | **NEW**: negligible bucket + Jenks over remainder, **or** zero-cost fallback: continuous ramp (can't produce one dominant class by construction) |
| `p_near_zero ≥ 0.20` OR `\|skew\| ≥ 1.0` OR `BC > 0.555` | **jenks**, k=5 |
| `0.5 ≤ \|skew\| < 1.0` | **quantile**, k=5 |
| `is_bounded_pct` AND `\|skew\| < 0.5` AND not multimodal | **equal-interval**, k=5 (round edges more legible than quantile's) |
| default | **quantile**, k=5 |

```
function selectClassification(m):
  if m.hasReference: return {method:"reference-anchored(NEW)", k:5, pin:m.referenceValue}
  if m.pNearZero >= 0.80: return {method:"negligible-bucket+jenks(NEW) | continuous(0-cost)", k:"1+4|cont"}
  if m.pNearZero >= 0.20 || abs(m.skewG1) >= 1.0 || m.bimodalityCoeff > 0.555:
    return {method:"jenks", k:5}
  if abs(m.skewG1) >= 0.5: return {method:"quantile", k:5}
  if m.isBoundedPct: return {method:"equal-interval", k:5}
  return {method:"quantile", k:5}
```

Precedence: reference > severe zero-inflation > skew/multimodal/moderate zero-inflation > moderate skew > bounded-symmetric > default. Only two branches need new capability; the rest route among the 4 shipped methods — a routing fix, not a rewrite.

## Q3. Log/Geometric-Interval and Percentile-Rank

**Geometric interval ≠ log transform.** Geometric interval builds class *widths* as a geometric progression from the minimum (tolerates zeros); a log(x) transform re-maps every value and is undefined at x≤0 (D3: "domain must not include or cross zero" — [D3 log scale](https://d3js.org/d3-scale/log)). Esri recommends geometric interval for "sparse datasets with many zero values and concentrated non-zero data" ([Esri](https://doc.esri.com/en/arcgis-pro/latest/help/mapping/layer-properties/data-classification-methods.html)) — near-literally buddhist_pct.

**When correct:** strictly-positive, ratio-scale, heavy-tailed data where comparison is multiplicative ("4x," not "+₹8,000") — upi_value_per_capita, banking deposits per capita. **When misleading:** log compresses colour-distance asymmetrically, squeezing the largest gaps into small colour-distance at the ramp's top — for this site it compounds the complaint, making already-tiny high-value urban districts also chromatically less distinct.

**Zero/negative handling:** (1) symlog (`d3.scaleSymlog()`) — linear near zero, log outside, needs legend disclosure of the extra parameter. (2) log(x+c) — c=1 is arbitrary, "the appropriate value ... has to depend on the scaling of x" ([Harvard Tagteam](https://tagteam.harvard.edu/hub_feeds/1973/feed_items/12381487)); c must be metric-specific. (3) Separate zero-bucket — Evans's (1977) named fix: treat zero as its own class, subdivide the remainder ([Evans 1977](http://www.casa.ucl.ac.uk/martin/msc_gis/evans_class_intervals.pdf)); needs a genuinely distinct colour, not "lightest ramp shade."

**Legend must disclose:** non-linear scale, labeled explicitly ([EU guide](https://data.europa.eu/apps/data-visualisation-guide/logarithmic-scales)); actual class-boundary values at each break; ideally a cumulative-frequency strip exposing lopsided occupancy ([Cromley & Cromley 2009](https://link.springer.com/article/10.1186/1476-072X-8-52)). Caveat: ~90% of readers in a 260-participant study "ignored the data-classification bias and relied on colour lightness only," legend or no legend ([Schiewe 2019](https://link.springer.com/article/10.1007/s42489-019-00026-y)) — legend fixes are a transparency floor, not a comprehension fix.

**Percentile-rank flattening danger.** Quantile/percentile-rank cuts on rank alone, blind to value gaps. On a near-uniform metric, 5-class quantile still manufactures five confident, evenly-sized, differently-coloured bands — the rule guarantees a full partition regardless of spread, and a reader infers geographic variation where none exists. Evans's closest warning: percentile maps "provide no information whatsoever about the frequency distribution ... incumbent on the cartographer to present a histogram alongside" ([Evans 1977](http://www.casa.ucl.ac.uk/martin/msc_gis/evans_class_intervals.pdf)). Legitimate use: genuinely ordinal questions ("top-decile districts") — CDC's Social Vulnerability Index ([ATSDR SVI](https://www.atsdr.cdc.gov/place-health/php/svi/svi-frequently-asked-questions-faqs.html)). Literature is split on quantile reliability generally: Brewer & Pickle (2002) found quantile most accurate for single-map reading (75.6%, best of 7 methods — [Brewer & Pickle](https://www.academia.edu/9199468/Evaluation_of_Methods_for_Classifying_Epidemiological_Data_on_Choropleth_Maps_in_Series)); Evans, summarizing Olson's experiments, found the reverse for cross-map comparison — likely different reader tasks, not reconciled in the literature. MapsOfBharat's mostly-single-map usage sits closer to Brewer & Pickle's task. **Verdict: quantile stays safe for symmetric/moderately-skewed metrics per Q2; do not add percentile-rank as a general option — reserve it, if ever built, for an explicit "district rank" feature with a mandatory companion histogram.**

## Q4. Number of Classes

Perceptual-limit literature converges on a 4–10 working range: Miller (1956) 7±2; Jenks & Knos (1961) "rarely exceed ten or fall below four"; Evans (1977) unambiguous at five or fewer; Mersey (1990) 5–9. Gilmartin & Shelton (1990), the hardest empirical numbers found: class-identification accuracy **91.9% at 4 classes vs. 68.2% at 8** ([Gilmartin & Shelton](https://scispace.com/pdf/choropleth-maps-on-high-resolution-crts-the-effects-of-186qtci52z.pdf)) — more classes is a pure accuracy loss; by hue, gray (84.5%) beat green (78.7%) beat magenta (72.8%). Declercq (1995), 3,240 classifications, GVF≥95% as "accurate": Jenks needs **≥6 classes** to clear it, rounded-break methods need **≥7**, most-rounded variant peaks at 7–9 — method-specific, not a blanket rule ([Declercq 1995](https://icaci.org/files/documents/ICC_proceedings/ICC1995/PDF/Cap173.pdf)). Equal-interval clears GVF≥95% only for normally-distributed input "regardless" of class count — no class count rescues it on skewed data. ~50% of published maps in Declercq's survey used 5 classes, ~20% used 6.

**Varies by n?** Sturges' Rule gives K≈10–11 for n=735, ≈6 for n=36 — but that's a histogram-binning formula; Declercq: "there is no consensus," and it runs above the cartographic-perceptual ceiling. The perceptual literature (4–10), not histogram-binning, governs a public map. **Varies by method/shape?** Yes — Declercq's method-specific GVF thresholds and Evans's organizing thesis (match method to shape, not one universal method+count).

**Is 5 defensible?** Yes — inside every cited ceiling, matches modal practice (~50% of surveyed maps), and Gilmartin & Shelton favor the low end for general-public audiences over Declercq's higher accuracy-optimal counts. **Not** defensible for severe zero-inflation classed with quantile — the defect is method choice, not count; no class count fixes buddhist_pct, only a different method does. **Verdict: keep k=5 fixed sitewide. Do not build a variable-class-count feature — no citable universal GVF threshold exists to drive it, and the real fix belongs in method selection.**

## Q5. Colour and Gradient

**Sequential vs. diverging is a rule, not a judgment call.** Sequential: ordered data, no meaningful centre. Diverging: only when a critical value splits the range into two qualitatively different regimes, pinned at that external value, not the data's midpoint ([ColorBrewer](https://www.personal.psu.edu/cab38/ColorBrewer/ColorBrewer_learnMore.html)). sex_ratio pins at 1000 (parity) — India's 2011 Census recorded **943**, below parity ([Demographics of India](https://en.wikipedia.org/wiki/Demographics_of_India)); mean/median-centering would silently normalize away the deficit the map should surface. A metric containing zero isn't automatically diverging — buddhist_pct's zero is the floor of a right-skewed distribution, not a centre; stays sequential.

**Is continuous/unclassed defensible? Yes, conditionally.** The classed-vs-unclassed literature is split (Peterson 1979 found better value understanding unclassed; Muller 1979 found readers self-sort unclassed maps into ~3 mental classes regardless; Dobson 1980 found unclassed causes "information overload" — [via Kelly review](https://cartographicperspectives.org/index.php/journal/article/download/cp86-kelly/1576?inline=1)), but that classed-favoring evidence is about matching colour to a static legend swatch — exactly what MapLibre's hover/tap tooltip (exact value + district name) removes as a failure mode. Continuous is defensible here specifically because of interactivity, conditional on: (1) a distribution-appropriate transform before mapping to colour when skewed/zero-inflated — a linear continuous ramp on skewed data reproduces "one colour dominates" exactly like equal-interval; (2) perceptually uniform lightness; (3) a legend showing distribution shape, not just min-max. For the static Canvas PNG export, default to classed (Jenks) — the tooltip mitigation doesn't exist on a shared static image.

**Palettes.** viridis/cividis are built in CAM02-UCS with monotonic lightness, avoiding a red hue path ([bids.github.io](https://bids.github.io/colormap/), CC0). cividis is explicitly optimized against deuteranomaly-simulated perception ([Nuñez et al. 2018](https://journals.plos.org/plosone/article?id=10.1371%2Fjournal.pone.0199239), CC BY 4.0). ColorBrewer remains legitimate, Apache-2.0, with a built-in colourblind-safe filter ([ColorBrewer](https://colorbrewer2.org/learnmore/schemes_full.html)). ~8% of men, ~0.5% of women have red-green deficiency ([Colour Blind Awareness](https://www.colourblindawareness.org/colour-blindness/types-of-colour-blindness/)) — rules out RdYlGn/Spectral/jet outright. **Verdict: viridis/cividis as sequential default; RdBu/PRGn/PuOr for diverging, never RdYlGn/Spectral.**

**Dark mode — converges on dedicated primary literature.** Schiewe (2024), n=214: the light-mode "dark-is-more" bias persists on dark backgrounds (87–93% compliance for a direct light-palette port), but **naive contrast-inversion performs worse** (51.8–52.8%, "brownish shifts") — a purpose-built dark palette matched the original's compliance while scoring higher on aesthetics ([Schiewe 2024](https://link.springer.com/article/10.1007/s42489-024-00171-z)). Recipe: background ~#252525 (not pure black); darkest class still >2:1 contrast against background (Schloss et al. 2025's "opaque-is-more" bias — too-faint low-value colour reads as translucent background, not a real low value — [Schloss et al. 2025](https://link.springer.com/article/10.3758/s13414-025-03172-w)); lightest class ~90% lightness, not pure white; hold saturation ~constant (~65%), let lightness carry the value signal; neighbouring-class ΔE00≈10. **Verdict: build the dark palette from these numbers directly — do not invert the light one.**

## Q6. Area-vs-Value Bias — Most Important

Mumbai City (157 km²) vs. Kutch (45,674 km²) is a **~291x area ratio** ([Mumbai City](https://en.wikipedia.org/wiki/Mumbai_City_district), [Kutch](https://en.wikipedia.org/wiki/Kutch_district)). On true-geography choropleth, Kutch outweighs Mumbai in retinal area by that ratio regardless of colour — area-size bias, a named phenomenon distinct from classification, one of three core choropleth cognitive biases in Schiewe's taxonomy ([Schiewe 2019](https://link.springer.com/article/10.1007/s42489-019-00026-y)); detection rates for maximum-value small regions run ~60–80% vs. ~90% for large regions in controlled testing ([Sponge Maps](https://link.springer.com/article/10.1007/s42489-022-00127-1)). No classification method fixes it.

**Legal framing — correcting a widely-repeated outdated claim.** Current Indian law (2021 DST Guidelines, 2022 National Geospatial Policy, both fetched and full-text-searched) requires "political Maps of India" to trace Survey-of-India boundary data, restricting labeling near ~51 sensitive-installation categories and a 25km border zone — nothing else. **Neither document specifies a penalty amount**; enforcement is only "dealt with under applicable laws" ([DST 2021](https://dst.gov.in/sites/default/files/Final%20Approved%20Guidelines%20on%20Geospatial%20Data_0.pdf)). The commonly-cited "7 years jail / ₹100 crore fine" belongs to the 2016 Geospatial Information Regulation Bill, **never enacted**, superseded by the liberalizing 2021 Guidelines — do not cite it as current exposure. Both current documents are silent on cartograms, thematic maps, or classification method. Zero India-specific cartogram precedent exists either way; every documented enforcement action (WorldMap Quiz app delisting 2023 — [MediaNama](https://www.medianama.com/2023/07/223-survey-of-india-google-playstore-app-inaccurate-map-india/); Twitter/X notice 2021; Ablo app removal 2025) targeted realistic-but-wrong *external* boundary depictions, never statistical distortion. One adjacent data point: a conventional (non-cartogram) Karnataka Congress map that merely cropped out PoK/Aksai Chin triggered major backlash in Nov 2024 ([Organiser](https://organiser.org/2024/11/09/264527/bharat/karnataka/karnataka-congress-led-government-under-fire-for-posting-distorted-map-of-india-on-social-media-platform/)) — visual shrinkage/omission of border-sensitive territory alone is a live reputational trigger. This matters directly for cartogram-family remedies, which by construction shrink exactly the huge, low-density, border-sensitive districts (Ladakh, Kargil, Arunachal Pradesh) toward slivers.

| Remedy | MapLibre cost | Mobile | SoI compliance | Verdict |
|---|---|---|---|---|

| Value-by-alpha | Trivial — one `fill-opacity` expression alongside `fill-color` ([MapLibre spec](https://maplibre.org/maplibre-style-spec/layers/)) | Degrades gracefully | Yes, unconditional | Fixes rural-false-dominance only; good complement |

**Verdict:** proportional symbols is the only remedy simultaneously small-cost, unconditionally compliant, and mobile-neutral — a circle's radius is a free variable tied only to the data value, structurally decoupled from the polygon. Cartograms are the literature's default reach, but the wrong first move here: largest cost, no mature JS tooling at India's scale, and real unresolved legal-plus-reputational risk concentrated in India's most sensitive geography. If built at all, cartograms must never be default or share-card, must carry explicit "not to scale" labeling, and need legal sign-off given the total absence of precedent either direction.

Cross-cutting pattern across the three well-documented agencies: normalize to rate/share, not raw count, specifically to avoid area bias (Eurostat's explicit rule); percentile-trim the colour-scale domain so single extreme districts don't stretch the ramp (Eurostat 10th/90th, OWID 5th/95th or 15th/99.5th); reference-midpoint diverging scales are first-class features at both Eurostat and OWID. **Verdict: MapsOfBharat's per-metric `default_scale` column is architecturally aligned with how the most sophisticated of these tools work — the gap is the decision rule populating it (Q2), not the mechanism.**

## Recommended Implementation Plan

**(a) Method-selection rule to ship now:** the Q2 table and pseudocode, computed offline at build time per metric. Two new capabilities required (reference-anchored manual classing; negligible-bucket-plus-Jenks for severe zero-inflation); everything else re-routes among the 4 methods already shipped.

**(b) Legend and disclosure changes:** show actual class-boundary values, not just endpoints; add a cumulative-frequency/histogram-strip mini-chart so lopsided class occupancy is visible; label non-linear scales explicitly wherever geometric-interval/log is used; on diverging maps, label the pinned reference value itself (e.g., "1000 = parity"); persist the hover/tap tooltip with exact value + district name on every map — the load-bearing mitigation that makes continuous ramps defensible (Q5) and the generic WCAG 1.4.1 answer regardless of remedy; don't treat legend fixes as sufficient alone — ~90% of readers read colour lightness only regardless of legend content ([Schiewe 2019](https://link.springer.com/article/10.1007/s42489-019-00026-y)).

**(c) The one area-bias remedy worth building: proportional/graduated symbols.** Wins on all three of Q6's axes (cost, mobile, compliance) simultaneously and is the only remedy that directly reverses the mechanism — decoupling visual weight from polygon area rather than working around it. Build: compute district centroids once from existing polygon GeoJSON; add a `circle` layer with `circle-radius` driven by a square-root scale (area-encoding, not radius-linear — readers underestimate raw area differences) via a MapLibre `interpolate` expression; sort features by radius descending before building the GeoJSON source (no built-in collision handling for circles); zoom-gate the layer (state zoom and below) to manage density clusters (NCR, Kolkata metro, the Northeast). Layer value-by-alpha (`fill-opacity` on the existing fill layer) underneath at trivial marginal cost — it fixes the complementary rural-over-dominance half the symbols don't touch. Add metro inset panels for the five densest cities as cheap polish, reusing the existing Canvas 2D export path rather than new live WebGL instances. Independently: add a searchable/typeahead district selector or sortable data table — WCAG 2.5.8 exempts digital maps from its 24×24px minimum target but "strongly encourages" a non-visual equivalent ([WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)), mitigating "hard to tap" for tiny districts regardless of which visual remedy ships.

**(d) Do not:**
- Ship cartogram-family remedies (contiguous, Dorling, hex-grid) as default or share-card — largest build cost, no mature JS tooling at India's scale, real unresolved legal ambiguity in border-sensitive geography.
- "Fix" zero-inflation/skew by adding more classes — Declercq and Evans both show this is a method-choice defect; buddhist_pct's 78.3% is arithmetic, not under-classification.
- Algorithmically invert the light-mode palette for dark mode — Schiewe (2024) measured this performing worse than a purpose-built palette (51.8–52.8% vs. 87–93% compliance).
- Apply raw log(x) to any metric with true zeros without symlog/additive-constant/separate-zero-bucket handling — log(0) is undefined.
- Use RdYlGn or Spectral for any diverging metric — both traverse the red-green CVD confusion axis affecting ~8% of men.
- Adopt dot density as a general per-metric renderer — fits only literal raw-count metrics, a minority of the ~150-metric catalog.
- Treat percentile-rank as a safe default for "always showing variation" — manufactures apparent variation on near-uniform data by construction.
- Build a variable-class-count feature — no citable universal GVF threshold exists to drive it, and k=5 is already defensible; the real defect is method choice, which `default_scale` already supports.

## Open Questions and Thin Evidence

- No cartography-specific skewness cutoff exists; Bulmer's 0.5/1.0 is borrowed from general statistics, not validated against choropleth reading outcomes.
- The 20%/80% zero-inflation thresholds are derived from this project's own k=5 — re-derive if class count changes.
- MAD multiplier (2.5x vs. 3.5x): genuine, unresolved disagreement between two actively-cited conventions.
- Brewer & Pickle (2002) vs. Evans/Olson (1970s) disagree on quantile reliability, likely due to different reader tasks — not reconciled in the literature.
- Indian data-journalism precedent for the small-dense-urban problem is unestablished — searches were blocked by proxy/TLS errors on NIC-hosted domains, a tooling gap, not a confirmed absence.
- Whether the 2021 Guidelines' boundary-data clause extends to thematic maps using administrative boundaries as a base layer (vs. maps about the boundary itself) is not disambiguated anywhere found — get counsel sign-off before any cartogram-family build regardless.
- ONS and Statistics Canada configs were unreachable (JS-gated SPAs) — thinner evidence for those two.
- No India-district-scale benchmark exists for any cartogram tool — prototype before assuming buildability, independent of the legal question.
- cividis's tritanopia performance is inferred, not literature-confirmed (cited work targets deuteranomaly only).
- Hartigan's dip test has no mature JS implementation; the bimodality coefficient used in Q2 is a cheap advisory-only proxy, not a validated substitute.
